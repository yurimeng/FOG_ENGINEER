# Requirement Analysis Process
需求分析流程

Document Version: v1.1
Last Updated: 2026-04-11
Change Log: v1.1 — 合并 Site Constraint Analysis，扩充为客户需求 + 部署环境二合一流程

---

## 1 目的

将客户需求和部署环境信息转化为完整的工程参数，用于方案设计。

两个维度：
1. **客户需求侧**：业务目标、算力规模、时间、预算
2. **部署环境侧**：电力、气候、场地、法规、物流

两个维度必须同时分析，缺一不可。

---

## 2 适用范围

所有预售基础设施项目：
- 边缘数据中心（Edge Datacenter）
- AI 训练集群
- AI 推理节点
- HPC 部署

## 3 输入清单

### 3.1 客户需求侧（来自 AM / RFI）

| 信息项 | 说明 | 是否必填 |
|--------|------|---------|
| 客户名称 | | 是 |
| 项目名称 | | 是 |
| 目标算力规模 | IT 负载（kW / MW），还是总设施负荷？必须澄清 | 是 |
| 部署模式 | 边缘部署还是集中部署 | 是 |
| 部署时间 | 目标交付时间 | 是 |
| 预算范围 | 仅作参考，不在方案中体现 | 否 |
| UL 合规需求 | 是否必须 UL 认证 | 是 |
| GPU / 服务器配置 | 具体型号和数量 | 是 |

### 3.2 部署环境侧（来自现场勘查 / RFI）

| 信息项 | 说明 | 是否必填 |
|--------|------|---------|
| 部署地点 | 国家/城市/具体地址 | 是 |
| 气候条件 | 全年温度范围、极端温度 | 是 |
| 电力可用性 | 市电容量（kVA）、电压等级、频率 | 是 |
| 场地条件 | 可用面积、地形地质、地面承重 | 是 |
| 水资源条件 | 是否可用冷却水、水质 | 否 |

| 当地法规 | 消防、环保、建筑审批 | 是 |
| 物流条件 | 运输路线、桥隧限高限重、吊装能力 | 是 |

## 4 流程步骤

### Step 1：收集客户需求（客户侧）

1. 收集客户业务目标和算力需求
2. 确认 IT 负载 vs 总设施负荷（**必须澄清**，见 [[FOG/KB/Guideline/POWER_SYSTEMS_Guideline|KB/POWER_LOAD]]）
3. 确认 UL 合规需求（影响选型：AC40 vs AC45）
4. 确认部署模式和期望时间线
5. 评估预算预期（仅供参考，不在方案中体现）

### Step 2：分析部署环境（环境侧）

1. **电力分析**
   - 确认市电接入容量（kVA）和可用性
   - 评估 Grid 稳定性（是否需要 BESS）
   - 确认电压等级和频率（380V/480V 等）

2. **气候分析**
   - 获取全年温度数据（干球/湿球温度）
   - 识别极端温度情况
   - 确定冷却设计温度（影响 PUE 和冷却方式）

3. **冷却可行性分析**
   - 环境温度 ≥28°C 时，Hybrid Cooling System 必须强制启动 DX
   - 水资源有限地区优先选择干冷器方案
   - 禁止纯干冷器方案（必须配置 Hybrid Cooling System）

4. **场地分析**
   - 可用面积是否满足模块布置（含维护通道）
   - 地面承重是否满足集装箱/设备要求
   - 噪声限制是否影响干冷器选型（住宅区/工业区）

5. **法规分析**
   - 建筑审批要求（是否需要建筑许可）
   - 消防规范（当地消防法规）
   - 环保要求（噪声、排水）
   - 电力接入审批

6. **物流分析**
   - 运输路线是否可行（桥隧限高限重）
   - 现场吊装能力
   - 海运/陆运条件

### Step 3：综合判断

将客户需求侧和部署环境侧的分析结果综合，判断：
- 是否满足客户目标算力
- 是否存在不可克服的约束
- 推荐配置方案

---

## 5 输出

### 5.1 需求侧输出

- 预计算力规模（IT 负载）
- 总设施负荷（IT 负载 ÷ PUE）
- 推荐产品选型
- 初步架构方向

### 5.2 环境侧输出

**电力可用性报告：**
- 市电接入容量（kVA）
- Grid 稳定性评估
- BESS 推荐配置（如需要）

**冷却可行性分析：**
- 推荐冷却方案（Hybrid Cooling System）
- DX 强制启动温度设定
- PUE 估算范围

**部署约束总结：**
- 主要场地约束及缓解措施
- 法规风险清单
- 物流约束及方案

### 5.3 关键决策

| 决策点 | 选项 | 判断依据 |
|--------|------|---------|
| 边缘 vs 集中部署 | 边缘 | 客户需求 + 场地条件 |
| 容器 vs 机房 | 容器（模块化） | 优先推荐，支持快速部署 |
| 浸没 vs DLC | 400kW 级：浸没；1200kW 级：DLC | 算力规模决定 |
| AC40 vs AC45 | 看 UL 合规要求 | 有 UL → AC45；无 UL → AC40 |
| BESS 配置 | Grid 稳定 → 无；不稳定 → BESS | Grid 稳定性评估 |
| Hybrid Cooling 配置 | 干冷器 + DX（必须）| 环境 ≥28°C 强制启动 DX |

## 6 风险清单

| 风险 | 描述 | 缓解措施 |
|------|------|---------|
| 信息不完整 | RFI 缺失关键信息导致设计偏差 | 上游流程中必须完整填写输入清单 |
| IT 负载 vs 总负荷混淆 | 选型和容量规划错误 | Step 2 必须明确澄清并输出两个数字 |
| 不现实的交付时间 | 客户期望与实际周期不符（185–230 天）| 在需求阶段明确告知参考周期 |
| Grid 不稳定 | 电力中断影响可用性 | 评估后推荐 BESS 配置 |
| 极端气候 | 环境温度超出设计范围 | 冷却设计必须基于极端温度，PUE 范围标注 |
| 法规审批延误 | 当地法规导致项目延期 | 提前识别合规路径和审批周期 |
| 物流不可行 | 超大模块无法运输到场 | 物流分析前置，必要时拆分模块 |

---

## 7 关键约束

1. **信息不完整不设计**：输入清单有一项"是否必填"为"是"的项目未填写时，暂停设计，等待补充
2. **IT 负载 vs 整体电力负荷**：必须在 Step 1 和 Step 2 中明确澄清，所有输出同时标注两个数字
3. **禁止纯干冷器方案**：Hybrid Cooling System 为强制配置
4. **PUE 必须输出范围**：不得写固定数字，由环境温度决定
5. **不输出价格**：需求分析阶段不涉及价格，成本相关转 AM
