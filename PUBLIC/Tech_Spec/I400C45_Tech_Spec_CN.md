## 1. Layout / 布局 ^sec-1-layout

I400C45 是**双舱布置**：45 英尺箱体前段为**算力舱**，后段为**专用电力舱**。算力舱内 8 台 I50TS 浸没槽沿两侧箱壁双排布置、每侧 4 台，中间留出运维通道；另设 1 台 10 kW 风冷机柜承载交换机与不便浸没的辅助设备。电力舱内装 600 kW EATON UPS 主机与 2 台 93LiG2 电池柜 —— **这就是 I400C45 比 I400C40 多出的那五英尺的全部内容**。

## 2. 产品定位 ^sec-2-positioning

**I400C45 是完整推理包：算力和电一起落地。** 它把 400 kW 的浸没算力核心与 600 kW 的 UPS / 电池后备封装在同一个 45 英尺箱体里，交付边界一次到位 —— 场站只需提供市电进线与室外冷源接口，箱内不再有需要客户另行采购、另行选型、另行报建的电力设备。对于没有既有配电室、或不愿为一个算力模块单独立项一套 UPS 工程的场地，这是最短的落地路径。

| 全 SKU ID | `I400C45SUT50` | ✅ 站点 |
| IT 容量 | 400 kW | ✅ 站点 |
| 构成单元 | 8× [[I50TS]] 浸没槽 + 1× 10 kW 风冷机柜 | ✅ 站点 |
| 单槽密度 | 50 kW（T50） | ✅ 站点 |
| 电力边界 | **箱内** —— 45ft 专用电力舱含 UPS 与电池 | ✅ 站点 |
| UL 合规 | ✅ UL compliant | ✅ 站点 |
| 状态 | shipped | ✅ 站点 |
| 典型场景 | 高密度 AI 推理；无既有配电室、要求电力边界随箱交付的场地；强制 UL 的市场 | ✅ 站点 |

### 2.1 与 I400C40 的差别 —— 只有两项

> **站点原文：** *"They share the same 400 kW, eight-tank core."*

I400C45 与 [[I400C40_Tech_Spec_CN|I400C40]] 的差别**只有电力边界，以及那五英尺（= 电力舱体积）**。八槽核心、油回路、槽内 CDU 冗余、冷却规则**完全相同**。不要把两者描述成两代产品或两种冷却架构。

| 项 | I400C45 | I400C40 |
|----|---------|---------|
| 八槽浸没核心 | **相同** | **相同** |
| 油回路与冷却规则 | **相同** | **相同** |
| 箱型 | 45ft（含专用电力舱） | 40ft |
| UPS 边界 | 箱内（600 kW EATON + 2× 93LiG2，~20 min） | 箱外（客户自备 600 kW，~10 min） |
| UL 合规 | ✅ UL compliant | 基准表记 "—"（不作为本 SKU 交付项） |

**选型判据：** 场站尚未为这 400 kW 建过配电与后备，或市场强制整机 UL → I400C45。场站已有既成的电力架构、UPS 与电池已在别处付过一次 → [[I400C40_Tech_Spec_CN|I400C40]]。

### 2.2 浸没线三个 SKU 的关系

| SKU | 全 SKU ID | 箱型 | IT | 槽数 | 单槽密度 | UPS 边界 |
|-----|-----------|------|-----|------|----------|----------|

### 3.1 IT Load vs Total Facility Load ^sec-3-it-vs-facility

| 口径 | 数值 | 含义 | 置信度 |
|------|------|------|--------|
| **IT Load** | **400 kW** | 8 个浸没槽内服务器 / GPU 的实际有功 | ✅ 站点 |
| **Total Facility Load** | 随 PUE 变化，**逐站点用 <https://mdcx.org>（TCO / Designer）计算** | IT + 槽内 CDU 泵功 + 室外排热（干冷器 / Hybrid Chiller）+ UPS 损耗 + 配电损耗 + 舱内辅机 | ✅ 裁定 |

> **报容量时永远给两个数。** 客户按 IT Load 采购算力，按 Total Facility Load 申请变电容量与做电费测算。I400C45 的 UPS 在箱内，UPS 损耗与电池柜散热**计在本箱设施负荷之内**（这一点与 I400C40 相反）。
>
> ⚠️ **PUE 一律写 `1.0x`（2026-08-30 Yuri 裁定 · 关闭 C-2）。** 原载的 ~440–500 kW 设施负荷区间与 §5 的 ≈1.05 **全部作废**。设施总负荷随 PUE 变化，**逐站点用 <https://mdcx.org> 的 TCO / Designer 计算，不给数字**。
>
> **但 IT Load vs Total Facility Load 的概念区分必须保留**（[[CLAUDE.md]] Hard Rule 5）—— 报容量时永远说明这是两个口径，只是设施侧那个数由计算器给。

## 5. 冷却系统 ^sec-5-cooling

I400C45 采用**单相浸没**：服务器整机浸入介电液，热量由槽内 CDU 的板式换热器交给设施水，再由室外冷源排入大气。没有服务器风扇，没有冷热通道，箱内不存在需要靠风量维持的热平衡 —— 这是浸没架构能在低干球站点做到极低 PUE 的物理前提（**具体 PUE 逐站点计算，见 §5.3**）。

### 5.1 两层回路

| 环路 | 介质 | 功能 | 置信度 |
|------|------|------|--------|
| 二次侧（油侧） | 单相浸没介电液 | 浸没服务器，经槽内 CDU 板换排热至设施水 | ✅ 站点 |
| 一次侧（设施水） | 设施水 / 乙二醇水溶液 | 接室外干冷器或 Hybrid Chiller | ✅ 站点 |
| 风冷支路 | 空气 | 1× 10 kW 风冷机柜，**不与浸没回路共用换热路径** | ✅ 站点 |

```
IT Load → 介电液（I50TS 槽内）→ 双 CDU 板换（2N）→ 设施水 32 / 37 °C
                                                          ↓
                              干冷器为主；峰值站点加 Hybrid Chiller
```

### 5.2 设计工况

| 项目 | 参数 | 置信度 |
|------|------|--------|
| 冷却方式 | 单相浸没 | ✅ 站点 |
| 槽内 CDU 配置 | **每槽双 CDU · 2N 完全冗余** | ✅ 站点 |
| 油侧 ΔT | **8 K** | ✅ 站点 |
| 单槽油流量 | **≈11–12 m³/h** | ✅ 站点 |
| 整箱二次侧流量（8 槽） | **≈88–96 m³/h** | 🔶 **derived** —— 由单槽 11–12 m³/h × 8 推出，设计值，以最终选型为准 |
| **设施水温位** | **32 / 37 °C 暖水** | ✅ 站点 —— **三个浸没 SKU 中只有 I400C45 有站点依据**，不得横向套用到 I400C40 / I200C20 |
| 室外冷源 | 干冷器为主；峰值站点加 Hybrid Chiller | ✅ 站点 |
| 设施水侧 ΔT / 流量 | ⏳ **#unconfirmed** | 等 Cooling Engineer 出具 I400C45 一次侧水力计算书；预期 TBD |
| 室外侧排热基线（kW） | ⏳ **#unconfirmed** | 等 Cooling Engineer 出具 I400C45 排热计算；预期 TBD |
| 设计环境湿球温度 | ⏳ **#unconfirmed** | 等 站点侧或 I400C45 DESIGN/ 披露设计湿球；预期 TBD |

### 5.3 PUE 与其适用边界 ^sec-5-pue

| 项目 | 参数 | 置信度 |
|------|------|--------|
| PUE | **`1.0x`** —— **不给固定值、不给区间、不给「典型值」。逐站点计算，入口 <https://mdcx.org>（TCO / Designer）** | ✅ 裁定 |

> **PUE 一律写 `1.0x`（2026-08-30 Yuri 裁定 · 关闭 C-2）。** 浸没线不存在统一的 PUE 数值，最终值由场地环境决定，**必须逐站点计算**。原载的「≈1.05 / ≤24 °C 干球边界」已作废，**不再引用**。
>
> 定性可说：干冷器可全年排热的气候落在低端；更热的站点需加混合冷机，PUE 相应上移。**但不给具体数。** 对客时给 <https://mdcx.org> 这个链接，不给数字。见 [[PRODUCT_SPEC_BASELINE#^baseline-pue]]。

### 5.4 冗余与故障模式

| 故障 | 影响 | 风险 |
|------|------|------|
| 单 CDU 故障 | 无影响（2N，另一台 CDU 承担全槽负荷） | 低 |
| 双 CDU 同时故障 | 该槽停机；其余 7 槽不受影响 | 高 |
| 室外冷源失效 | 设施水温上升，需降载或停机 | 中 |
| 板换 / 过滤器堵塞 | 换热效率下降，油温抬升 | 中 |

> **槽内冷却是 2N，箱内 IT 不是。** 单箱不设 IT 冗余 —— 详见 §6.3 冗余模型。

### 5.5 冷源配置原则

每台 I400C45 与其 Cooling Zone **一对一**配置室外冷源，不跨箱共享冷源。系统级可用性靠**增加箱数**实现，不靠共享冷源做冗余。

## 6. 配电规格 ^sec-6-power

I400C45 的电力边界在**箱内**。600 kW EATON UPS 与 2 台 93LiG2 电池柜装在专用电力舱内，客户侧只需把市电（及可选发电机 / BESS）接到箱体进线柜。

### 6.1 电力路径

```
Grid（可选 ATS ← Generator / BESS）
        ↓
I400C45 专用电力舱：EATON UPS 600 kW + 2× 93LiG2 电池（~20 min）
        ↓
箱内 PDC → 8× I50TS 槽内 PDU（A/B 双路）+ 10 kW 风冷柜 + 辅机
```

| 项目 | 参数 | 置信度 / 闭环 |
|------|------|----------------|
| UPS 边界 | **箱内**（45ft 专用电力舱） | ✅ 站点 |
| UPS 容量 / 品牌 | **600 kW · EATON** | ✅ 站点 |
| 电池后备 | **~20 min**（内置，2× 93LiG2） | ✅ 站点 / KB |
| UL 合规 | ✅ **UL compliant** | ✅ 站点 |
| UPS 具体型号 | ⏳ **#unconfirmed** | 等 站点侧或 Power Engineer 确认 I400C45 的 UPS 型号款式；预期 TBD |
| 供电制式（进线电压） | ⏳ **#unconfirmed** | 等 站点侧在浸没产品页披露供电制式（基准表 §1.3 的 380 / 400 / 415 / 480 V AC 一行只覆盖液冷线）；预期 TBD |
| 母线 / PDC 规格 | ⏳ **#unconfirmed** | 等 Power Engineer 出具 I400C45 配电系统图与计算书；预期 TBD |
| 舱内电气负荷分项表 | ⏳ **#unconfirmed** | 等 Power Engineer 出具 I400C45 工作负荷表；预期 TBD |

> ⚠️ **UPS ≠ BESS。** 93LiG2 是分钟级切换后备；BESS 是小时级储能，属 Power Zone 范围，不在本箱内。二者不可混称（[[CLAUDE.md]] Hard Rule 7）。

### 6.3 冗余模型 ^sec-6-redundancy

> **集装箱是最小冗余单元。** 这是浸没线的冗余口径，来自 [[PRODUCT_SPEC_BASELINE#^baseline-immersion-cooling]] §3.3。

| 层级 | 冗余 | 置信度 |
|------|------|--------|
| 槽内冷却（每 I50TS 双 CDU） | **2N** | ✅ 站点 |
| 单箱 IT | **不设 IT 冗余** —— 单箱是一个整体，箱内不做 N+1 | ✅ 站点 |
| 系统级 | **N / N+1 / 2N 靠增加箱数实现** | ✅ 站点 |
| 设计目标 | Tier II 投资，经差异化冗余达到 Tier III 级可用性 | ✅ 站点 |
| 冗余原则 | 失效代价高的地方 2N，其余 N+1 —— **不做全局 2N** | ✅ 站点 |

**对客话术：** 客户问「你们是不是 2N」，答案不是是或否，而是「哪一层」。槽内冷却是 2N；IT 层面，冗余单位是箱 —— 需要 N+1 就买 N+1 台箱，需要 2N 就买 2N 台箱。这样客户为冗余花的钱买到的是可用算力，而不是闲置的箱内设备。
