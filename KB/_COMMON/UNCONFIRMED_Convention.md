# `#unconfirmed` 标注规范

> **为什么需要这份规范：** vault 里同时存在三类数值 —— 有权威来源的、由我方推导的、以及等厂家或等站点回复的占位值。三类混在同一张表里，读者无法判断哪一行可以直接对客报出。本规范把「置信度」变成显式的、可 grep、可在 Obsidian 里按 tag 聚合的元数据。
>
> 本规范由 2026-08-30 全 vault 同步引入。此前散见于 [[STD_L1240C45]] §冲突标记区 的行内 `unconfirmed` 写法是它的前身，语义一致，现统一到本规范。

## 1. 三个层级的标注位置

`#unconfirmed` 在三个不同粒度上使用，含义逐级收窄：

| 粒度 | 写法 | 含义 | 示例 |
|---|---|---|---|
| **文档级** | frontmatter `tags:` 中加 `"#unconfirmed"` | 整份文档的核心结论尚未证实，**不得整份外发** | [[PRD-STULZ-CW330]] |
| **章节级** | 章节标题后加 `#unconfirmed` | 该节全部数值待证实，其余章节可用 | Tech Spec §7 结构规格 |
| **行级** | 表格行的备注列写 `⏳ #unconfirmed` | 仅该行待证实 | 单行运行海拔 TBD |

> **不要只在正文里写"待确认"三个字。** 中文描述无法被 tag 检索聚合。要么打 `#unconfirmed`，要么就是已确认 —— 没有中间态。

^unconfirmed-levels

## 2. 四级置信度标记

行级备注列统一使用下列四个标记之一，**不引入第五种**：

| 标记 | 含义 | 可否对客 | 谁来闭环 |
|---|---|---|---|
| ✅ | **已确认** —— 有权威来源（厂家书面 / 站点 Locked 文档 / 已签署图纸） | 可 | — |
| 🔶 **derived** | **我方推导** —— 由已确认值按公式或工程判断推出，非厂家原始数据 | 可，但须注明"设计值，以最终选型为准" | 出该推导的工程师 |
| ⏳ **#unconfirmed** | **待证实** —— 等厂家回复 / 等站点锁定 / 等实测 | **不可** | 备注列须写明等谁、等什么 |
| ⛔ **conflict** | **源冲突** —— 两份及以上来源给出不同值，尚未裁定 | **不可** | 须升级到对应 STD 文档裁定 |

^unconfirmed-levels-4

### 与既有写法的关系

- [[STD_L1240C45]] 的 C1–C11 冲突表用的 `⏳ **unconfirmed**` 即本规范的第三级，**不需改写**，但新增行请补 `#` 前缀以便检索。
- 各 PRD 的 `Q1–Qn 澄清项` 表是 `⏳ #unconfirmed` 的展开形式：Q 表列"等谁、等什么"，正文表格只标状态。两者必须一一对应。

## 3. 必填的三个字段

任何 `⏳ #unconfirmed` 标记**必须**同时给出三项，缺一不可：

| 字段 | 说明 | 反例（不合格） |
|---|---|---|
| **等谁** | 具体到组织或角色：STULZ / TICA / 站点侧 / Cooling Engineer | "待确认" |
| **等什么** | 具体到交付物：CE DoC 证书编号 / 选型书 / 实测报告 | "更多信息" |
| **预期时点** | 日期或事件；未知写 `TBD` 但不得省略该列 | （空白） |

> 例：`⏳ #unconfirmed —— 等 STULZ 提供 CW330 选型书与外形图，预期 2026-09-01（周一）`

## 4. 闭环流程

```
标注 ⏳ #unconfirmed
      ↓
   收到来源材料
      ↓
   ┌──────────────┬───────────────────┐
   │ 与现有值一致  │ 与现有值冲突       │
   ↓              ↓                   
 改为 ✅        改为 ⛔ conflict
 移除 tag       升级到 STD 裁定
 记 Changelog   裁定后才改 ✅
```

**三条硬规则：**

1. **移除 `#unconfirmed` 必须同时记 Changelog**，写明来源材料是什么。悄悄把 ⏳ 改成 ✅ 等同于伪造来源。
2. **文档级 tag 只有在该文档所有行级标记清空后才能移除。** 还剩一行 ⏳，文档级 tag 就得留着。
3. **对客外发前必须 grep 一次 `#unconfirmed`。** 命中即停，走 §5 的降级输出。

## 5. 对客输出时怎么处理

| 情形 | 处理 |
|---|---|
| 该参数客户没问 | **整行删除**，不要输出带 ⏳ 的表格给客户 |
| 该参数客户问了，但我方确实没有 | 写"该参数以最终选型为准，将在技术澄清阶段提供"，**不给数字** |
| 该参数是 🔶 derived | 可给，但必须写"设计值" |
| 整份文档带文档级 `#unconfirmed` | **不外发**。需要对客材料时另出摘录版，只保留 ✅ 与 🔶 行 |

> 与 [[CLAUDE.md]] Hard Rule 1（NO PRICE）同级：**带 ⏳ 的数字不出门**，和价格一样。

^unconfirmed-external

## 6. 检索方式

```
# 全 vault 找所有待证实项
grep -rn "#unconfirmed" --include="*.md" .

# 只找文档级（frontmatter 里的）
grep -rln -B0 -A0 '^\s*-\s*"#unconfirmed"' --include="*.md" .

# 找不合格的标注（有 ⏳ 但没写等谁）
grep -rn "⏳" --include="*.md" . | grep -v "等"
```

Obsidian 内直接点击 `#unconfirmed` tag 可聚合全部命中。
