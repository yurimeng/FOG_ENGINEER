# 5. MDC Deployment Architecture（MDC部署架构）

MDC 的部署架构描述多个模块如何组合、扩展，并最终形成 AI Factory 规模的算力园区。

本章不重复单模块的工程实现细节（参见第4章），而是聚焦：

- 从单模块到园区的**层级组合逻辑**
- 不同规模下的**部署形态与适用场景**
- 园区级的**基础设施共享策略**
- **扩展路径**与资本投入节奏

---

## 5.1 部署层级（Deployment Hierarchy）

MDC 部署体系分为四个层级，每个层级都可以独立存在，也可以向上组合：

```text
┌─────────────────────────────────────────┐
│          AI Factory Campus              │  ← 多个 ACC 组成超大规模算力基地
├─────────────────────────────────────────┤
│     ACC（Advanced Computing Cluster）   │  ← 多个模块 + 共享冷却/电力
├─────────────────────────────────────────┤
│       Module（AC40 / DC45）             │  ← 独立算力单元，可独立运行 ^mdc-a09c175dd7
├─────────────────────────────────────────┤
│       Infrastructure（场地接入）         │  ← 电力 / 冷却 / 网络接入点
└─────────────────────────────────────────┘
````

层级设计的核心原则是：**每一层都可以独立交付，上层通过增加下层模块数量来扩展**， 而不需要改变已部署的系统架构。

---

## 5.2 单模块部署（Single Module Deployment）

单模块是 MDC 的最小可部署单元。

适用场景：

|场景|说明|
|---|---|
|快速验证|客户首次采购，验证MDC在本地的适配性|
|边缘算力|靠近数据源或用户的小型推理节点|
|矿场改造第一步|利用既有电力和场地先行部署|
|资本约束场景|最小化初始投入，后续按需扩展|

单模块部署只需要三个外部接入条件：

```text
电力接入（MV 或 LV）
    +
冷却接入（Supply / Return 水管）
    +
网络接入（Fiber uplink）
```

模块本身包含完整的 UPS、冷却控制、配电与监控系统，无需额外机房基础设施。

---

## 5.3 ACC 园区部署（Campus Deployment）

当多个模块组合时，形成 ACC（Advanced Computing Cluster）。

ACC 是 MDC 的标准园区单元，由以下组件构成：

```text
ACC
 ├── AC40 Module × N    （推理 / 分布式训练） ^mdc-c3c01b64f9
 ├── DC45 Module × N    （大规模训练） ^mdc-27bd8416cc
 ├── Cooling Plant       （共享冷却站）
 └── Power Infrastructure（共享变压器 / BESS / Generator）
```

### 5.3.1 园区级资源共享策略

在 ACC 规模下，部分基础设施可以在模块间共享，以降低整体成本：

|基础设施|共享策略|说明|
|---|---|---|
|变压器 / MV 接入|可共享|按总功率规划，支持模块逐步上线|
|BESS|可共享|园区级 BESS 统一调度，削峰填谷|
|柴油发电机|可共享|按最大负载配置，支持全园区备用|
|Dry Cooler / Chiller|可共享|冷却站集中建设，管道分配至各模块|
|CDU（DC45专属）|不共享|每个 DC45 模块独立 CDU，避免冷却耦合 ^mdc-47b811e833 |
|UPS（模块级）|不共享|每个模块独立 UPS，故障不跨模块传播|

**设计原则：共享基础设施降低成本，不共享关键保护路径保证可靠性。**

### 5.3.2 典型 ACC 规模参考

|模块数量|典型 IT 功率|典型 GPU 数量（参考）|适用场景|
|---|---|---|---|
|1|~360–480 kW|~500–1,000 GPU|单站验证 / 边缘节点|
|2–4|~1–2 MW|~2,000–4,000 GPU|区域推理集群|
|8–16|~4–8 MW|~8,000–16,000 GPU|中型 AI Training 集群|
|32–64|~16–32 MW|~32,000+ GPU|AI Factory 规模|

_以上为参考估算值，实际以模块配置与 GPU 规格为准。_

## 5.4 扩展路径（Scaling Path）

MDC 的扩展遵循**线性增量模式**：每次扩展只需新增模块，无需改动已运行的系统。

典型扩展路径：

```text
阶段 1：1 个 AC40（推理优先，快速上线） ^mdc-a07485c5e5
    ↓
阶段 2：增加 1–2 个 DC45（引入训练能力） ^mdc-f60ac31710
    ↓
阶段 3：继续增加 AC40 / DC45（按业务需求混合扩展） ^mdc-058aa0c18f
    ↓
阶段 N：形成完整 AI Factory 园区
```

扩展时的关键设计约束：

- **电力主接入需按最终规模预留容量**，否则后期扩容需重新接入MV
- **冷却站可分期建设**，但管网主干应按目标规模预埋
- **网络 Fabric 扩展需提前规划拓扑**，避免训练集群扩展时重构

## 5.5 混合算力园区（Hybrid Compute Campus）

AI Factory 通常同时运行训练和推理任务，MDC 支持在同一园区内混合部署 AC40（Immersion）与 DC45（DLC）： ^mdc-31561fe11a

```text
┌──────────────── ACC Campus ─────────────────┐
│                                              │
│  ┌─────────────┐    ┌─────────────────────┐  │
│  │    AC40     │    │        DC45         │  │ ^mdc-484e548e06
│  │  Immersion  │    │    Direct Liquid     │  │
│  │  推理集群    │    │    训练集群           │  │
│  └──────┬──────┘    └──────────┬──────────┘  │
│         │                      │             │
│  ┌──────▼──────────────────────▼──────────┐  │
│  │        共享 Cooling Plant               │  │
│  │    Dry Cooler / Hybrid Chiller          │  │
│  └────────────────────────────────────────┘  │
│                                              │
│  ┌────────────────────────────────────────┐  │
│  │     共享 Power Infrastructure           │  │
│  │  Transformer / BESS / Generator        │  │
│  └────────────────────────────────────────┘  │
└──────────────────────────────────────────────┘
```

混合园区的冷却系统可以统一使用高温水系统（28–35°C Supply）， AC40 和 DC45 均在此温度范围内正常工作，无需分别建设冷却回路。 ^mdc-db66d7f461

## 5.6 运维控制架构（Operations Architecture）

AI Factory 规模的 MDC 需要统一的控制体系，分三个层级：

```text
┌─────────────────────────────────────────────┐
│         AI 算力调度平台（资源层）             │
│   GPU 资源调度 / 任务编排 / 算力计费         │
└───────────────────┬─────────────────────────┘
                    │ 资源状态 / 健康数据
┌───────────────────▼─────────────────────────┐
│         DCIM（数据中心基础设施管理）          │
│   设备资产 / PUE监控 / 容量规划 / 告警管理   │
└───────────────────┬─────────────────────────┘
                    │ 传感器数据 / 控制指令
┌───────────────────▼─────────────────────────┐
│         BMS（楼控系统）                       │
│   冷却控制 / 电力监控 / 环境传感 / 泄漏检测  │
└─────────────────────────────────────────────┘
```

三层职责分工：

|层级|职责|控制对象|
|---|---|---|
|BMS|物理系统稳定运行|冷却泵、风机、PDU、传感器|
|DCIM|基础设施效率与健康|模块级PUE、容量利用率、告警|
|算力调度|算力资源最大化利用|GPU集群、任务队列、租户隔离|

数据流方向：BMS 向上汇报物理状态，DCIM 向上汇报基础设施状态， 算力调度平台基于上层信息进行资源编排，控制指令向下传递。

---

## 5.7 部署架构总结

MDC 部署架构的核心逻辑是：

**以模块为原子单元，以 ACC 为标准园区单元，以线性扩展替代预建设。**

|维度|设计选择|目标|
|---|---|---|
|扩展方式|增加模块，不升级单体|降低扩展风险|
|资源共享|基础设施共享，保护路径独立|平衡成本与可靠性|
|混合算力|AC40 + DC45 同园区部署|覆盖推理与训练全场景 ^mdc-b124c30ea3 |
|运维控制|BMS → DCIM → 算力调度三层分离|清晰职责边界，支持规模化运维|
